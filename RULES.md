# RULES.md — the rules every NovaTrail repository shares

Every NovaTrail repository's CLAUDE.md imports this file: spec's as `@RULES.md`, every other repository's as `@spec/RULES.md`, from spec checked out as a git submodule at an exact tag. A repository's role and its own documents are in its CLAUDE.md; what follows holds in all of them. The file changes only in spec, and a repository takes the new version with a new tag of spec.

spec's documents are under `docs/` in spec itself and under `spec/docs/` everywhere else.

## The bar

Every document meets one bar and is written for whoever reads it. The documents under `docs/`, but for the epic archives `docs/plan/`, are read by a session of Claude Code, not by the author, and so are the rules and tables of the work plan — RUN.md, `run/` and spec's COORDINATION.md —, which are terse, for the session: it acts on them for an engineer, a module author or a lawyer. Write them so that it can do so without asking what you meant, and shape them to be read in parts, a section or an entry at a time. The bar is concrete:

- one term means one thing in every document; the vocabulary is the glossary of spec's `docs/concepts.md`;
- a fact no run of ours checks — a law, a regulator, terms, a price, a license, a page with no version — cites its one record of `docs/sources.md`, `sources 2.3`: its address, the date read, a quote; a program's documentation or code at a version or commit is a link beside the claim, a test or a measurement its evidence, NovaTrail's and MathTrail's files git;
- a gap is never filled silently: it becomes an open question with options and a recommendation;
- a decision says why, and what was rejected;
- each fact has one home, and a text holds the current state, not its history: a document names the file where a value is set — `deploy/*.json`, the submodule, `package.json`, a Dockerfile's `ARG` —, not the value, and keeps no chronicle; the history is git, the releases and the archives;
- a code comment says only what the code cannot — why, a constraint, a pitfall, an exported API's contract —, never the code again, its history, its task, a decision or a section of a document: its reason stands in words.

The texts people read are written for them: spec's legal texts in `legal/`, the normative texts for authors, README files, the bodies of the plan's tasks, the order of spec's COORDINATION.md, the epic archives and the reports to the author.

## The project

NovaTrail is a universal open platform for adaptive learning, interactive lessons and AI tutoring, for any subject and any age. A subject comes as a module — data, not code and not instructions to a model. A program decides every verdict; the AI only reads the learner's work and words the tutor's replies. NovaTrail succeeds MathTrail, olympiad maths for grades 1–6, which is frozen; its ideas, code and content are carried over selectively. The platform is split into repositories from day one, and `spec` is their shared source of truth; which repositories there are and what they are called is spec's `docs/repositories.md`.

The name is written **NovaTrail**, with a capital T. Identifiers stay lowercase: the organization `altnovatrail`, `novatrail-spec`, `NOVATRAIL_DEVCONTAINER`.

## How we work

- The author runs tasks one at a time: «Выполни задачу Txx из RUN.md». Do only that task, by the rules in RUN.md. An epic across repositories runs itself: «Сделай эпик E…» in spec's orchestrator container.
- One task is one session: its planning and execution run in one session of Claude Code, an inbox triage in the session it was started in, and the next task in a new session or after `/clear`. The hook `UserPromptSubmit` of `.claude/settings.json`, spec's `tools/session/`, stops a prompt that starts another task in the same session and names `/clear`. What the next task needs from this one lives in files, not in the session.
- Before proposing a change, read the repository's decision log, `docs/decisions.md`, and the sections the change touches. Do not re-propose what a decision rejected without new evidence. If a decision has to change, ask the author.
- A decision is its text in force, with its why and what it rejected. A change rewrites the entry in its place, and every entry it changes too; git keeps the old text, and the commit says why; no dated amendment is written.
- A new number — R, О-, П-, Т- — is the next one still free when it is written down, not when the work began. Each register's opening names the next free number; keep it current.
- A fact comes from the primary source. Read again, the same text changes a record's date; another rewrites the claims on it at once and drops the old reading, unless an open question holds both. A record's number is never given again. What could not be verified is not stated as fact: it becomes an open question. The results of a measurement go to `docs/measurements.md`, which the first measurement starts: `docs/architecture.md` holds neither.
- A run longer than a few minutes — tests, a simulation, a build, CI — goes to the background, and the session waits for its notification or a Monitor of its condition, never a `sleep` loop in the foreground: each call that polls rereads the whole context. The orchestrator's executor waits in the foreground, by its contract.
- Plan for the fewest pull requests and rounds of CI: tasks of one repository in a row, none waiting on another, share one branch and one pull request; a pull request of its own is only where a dependency needs it. What can run locally runs first: CI confirms, it does not find. The bookkeeping goes in before the first round, a fix after its local check: one round a pull request.
- Code comes with its tests: a pull request that adds or changes code adds or changes the tests of its automated suite too. Where a repository's coverage goes to Codecov, the merge waits for `codecov/patch`, at least 90% of the changed lines covered.
- Do not commit: the author commits after review, unless the author's word, as «доведи до мержа», says otherwise. «Сделай эпик E…» says it for each task it runs: its executor opens the pull request, the orchestrator merges it on green checks; a task across repositories pushes each change and ships on the author's «да».
- Finish with a short report to the author in Russian: what was done, which files, what is still open.

## Citations

A text gives its reason in words and stands by itself; who decided what, and when, is git's history. Outside the work plan — RUN.md, `run/` and spec's COORDINATION.md — and the epic archives `docs/plan/`:

- No decision's number — the repository's own, spec's, another NovaTrail repository's or MathTrail's — stands in `docs/`, a README, CLAUDE.md, RULES.md, a rule of `.claude/rules/`, code and its comments, the devcontainer, a `.proto` file or a schema's description. A decision log gives an entry's number in its heading alone, and an entry cites no other entry.
- No section and no document is cited: what a text needs from another, it says in words. The one exception is a fact no run checks, or a measurement, which cites its one record, `sources 2.3` or `measurements 1.4`, and from another repository spec's record as `sources 2.3 spec`. Naming the file where a thing lives is no citation.
- No task's number and no dated attribution or amendment — "the author's decision of <date>", "the amendment of <date> to …".
- The open questions О-, П- and Т- of spec's registers and the rows Д and В of `run/` name open work, and stand anywhere. A repository other than spec keeps no register of open questions: what it has still to decide is listed in its `docs/architecture.md`.
- The normative texts for authors whose versions in force never change — `legal/`'s texts in force, the prose of `format/`, `admission/`, `deployment/`, `consent-age/` and `export/` — stand outside the rule too; the comments of a `.proto` file do not: editing one changes no contract.
- An example of a citation is written in code — `R03`, `architecture 2` —, which the documents check does not take for one; it checks the rule where `docs-budgets.json` sets `"citations": true`.
- MathTrail's repositories, `github.com/mathtrail/canvas-api` and `github.com/mathtrail/mathtrail-standalone`, are cloned into a temporary directory, never into a NovaTrail repository.

## Across repositories

`spec` is what every repository shares: the vocabulary, the formats and contracts, the platform's documents and decisions, and these rules. Outside spec it is read-only, at the tag the repository pins, and a session changes neither spec nor any other repository from where it works, but for the merges of spec's orchestrator and a task across repositories.

- Some things belong in spec: a question that concerns more than one repository, a decision that settles one of spec's open questions, and any change to a component's card in spec's `docs/architecture.md`. Outside spec, the session writes such a thing into table 3 of its plan, `run/QUESTIONS.md`, its question opening with the mark «В реестр spec», with its options and recommendation, and names it in its report. Nobody carries it: on the author's word, or at the end of spec's epic, spec's session reads every repository's table 3 on GitHub's main, and the author decides and numbers the new rows. Whatever else a session has for spec goes the same way, as a row of table 3: what a repository took with a move to a tag, spec sees by its submodule.
- A component's card in spec's `docs/architecture.md` is the summary; the repository's own `docs/architecture.md` is the detail. When the detail changes what the card says — what the component does and does not do, its data, its links — the card changes too, by the same route.
- A repository moves to a newer tag of spec on purpose, in a task of its own: its commit says why, and the lines of its CLAUDE.md and RUN.md that name the tag change with it; it is no entry of the log.

## Hard rules

- **Devcontainer only.** All work happens inside the devcontainer (`.devcontainer/`). If `NOVATRAIL_DEVCONTAINER` is not `1`, you are on the host: stop and ask the author to "Reopen in Container". "The change is only documents" is no reason to go on. The one exception is a cloud session of Claude Code that the author started for the task: it works without the container, and its report names every check it could not run. The orchestrator's executor runs by `docker exec` in its repository's container; the orchestrator's own holds the host's Docker socket, root on the host, and opens no code but NovaTrail's.
- **Exact versions only.** No `latest`, floating tags or ranges. Images are pinned by tag and digest, tools by exact version, each where it is installed: an `ARG` in `.devcontainer/Dockerfile`, a literal in `.devcontainer/devcontainer.json`. An archive the Dockerfile downloads is checked against its sha256, an `ARG` beside its version for each architecture, before it is unpacked. A system package apt installs comes from a snapshot of the Ubuntu archive alone — a source of its own whose URI names the snapshot's ID, an `ARG` beside the list of packages — and the ID is raised by hand like a version.
- **Production images.** An image that runs in production — a Cloud Run service or its jobs — is a static Go binary, built with `CGO_ENABLED=0` and `-trimpath`, on `gcr.io/distroless/static-debian13:nonroot` pinned by its digest: no shell, no package manager, not root, and nothing in it beyond the binary and what the repository's own decisions put there. Docker Hardened Images are not used. Any other runtime comes only by a change of spec's decision on production images, to the same bar. NovaTrail publishes no image: the base holds files under GPL-2 and MPL-2.0, which a published image would distribute. A service's release carries its signed binary and the `Dockerfile`; whoever deploys builds the image around the binary that `release-verify` accepted and keeps it in a private registry of their own.
- **Language.** The work plan — RUN.md and the tables of `run/` — and spec's cross-repository plan, COORDINATION.md, are in English; in Russian are the bodies of tasks in table 1 and in `run/TASKS.md`, the section «Порядок» of COORDINATION.md and the epic archives `docs/plan/`. The documents under `docs/` are in English, for the Claude Code session that reads them: a document still in Russian stays so until a task of its own translates it, by spec's `tools/translation/README.md` and with `just -f spec/justfile translation-check` (in spec, `just translation-check`). A quote of a source stays in its own language, and the prefixes О-, П-, Т-, Д and В stay Cyrillic. Everything else — README.md, CLAUDE.md, AGENTS.md, RULES.md, code, comments, schema descriptions and prompts — is in English, and so are the normative texts for authors: the module format in spec's `format/`, the widget protocol and the guides. Commit messages, issues and a pull request's title and description are in English, a person's too, and a session's terse; reports to the author are in Russian.
- **No learners' data in the repository.** No learner's name, work, handwriting, voice or photo, no email or account identifier — not even in examples, which are synthetic.
- **No secrets in the repository.** Keys and tokens live in environment variables or a secret manager, never in a committed file.
- **Release files are verified.** A file of a NovaTrail release — a binary, an archive, an index — enters code or CI only once `just -f spec/justfile release-verify` has accepted it (in spec, `just release-verify`), where it enters NovaTrail; a package of `@altnovatrail` from npm, once `release-verify-npm` has accepted the lock file, in CI of the pull request that changes it. From then on the digest the check pinned holds the file — the lock file's `integrity`, the chain of digests from a pinned index — and nothing checks its signature again: `module-kit`'s library checks none.
- **Licenses.** Everything is Apache-2.0 — code, documents and the official modules' content. One exception is the code of conduct in `.github`, the Contributor Covenant 2.1 with its placeholder for how to report filled in, under that text's license, CC BY 4.0. Add only dependencies whose licenses are compatible with Apache-2.0. A development or CI tool that never ships and puts none of its own code into what ships — a checker, a browser for tests — may carry another OSI-approved license or free terms, for open source or for everyone, only as a named exception, in the license check or in the decision that brings it in; free terms, only while no image or archive that NovaTrail publishes holds the tool and NovaTrail can be built, run and deployed without it. The sign-in service's mark on its own button, Google's "G", ships in `app` only as the service's brand rules allow, named in `app`'s NOTICE as its trademark. The licenses of third-party modules are open (О-10).
- **Loading.** What an interface awaits from an asynchronous load is a skeleton, never a blank or a spinner.
- **Learners' data first.** Anything that touches a learner's data is read against spec's `docs/privacy.md` before it is proposed.
