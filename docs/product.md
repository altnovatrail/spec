## 1. The gist

**What it is.** NovaTrail is an open platform on which any subject becomes an interactive lesson with an AI tutor: maths, Spanish, physics, drawing — for children and for adults.

- A subject comes as a **module**: a skill graph, lessons, tasks, typical mistakes, techniques and a canvas kind. Any author can write a module (R02).
- The learner works on a **canvas**: writes by hand, draws, types text, moves objects, speaks.
- The **AI tutor** reads the learner's work and talks with them in text and voice. Whether an answer is correct is decided by a program by the task's key, not by the model (R03).
- The **learner model** brings the skills of all modules together, and the **engine** chooses the next lesson or task.

**The main idea: a module is data for the engine, not an instruction to a model.**
- A Claude skill is instructions that a model carries out as it understood them.
- A NovaTrail module is data checked by a schema, which the platform carries out the same way every time. The same module of the same version and the same learner state give the same choice of task and the same verdict on the same reading of the work.
- AI works only at the input, where it reads the work, and at the output, where it chooses the words (R03).

**How it differs:**
- **from a chat with AI:** a chat has no key, no learner model and no path through skills; it may give away the answer and get the check wrong;
- **from drill apps with tests:** the learner solves freely — by hand, in words, on a stand — and the tutor looks at the course of solution, not only at the answer;
- **from courses:** the path is adaptive — by the skill graph and the learner model, not by a common plan;
- **from a private tutor:** available every day and cheaper. A private tutor, moreover, can become a module author or guide a learner together with the platform.

## 2. Where we came from

**MathTrail** is a family of products for olympiad maths for grades 1–6 (the organization `mathtrail` on GitHub):
- **mathtrail-standalone** — a free open app for Claude and ChatGPT. The chat's model writes the tasks, and a program checks them with a solver. Here live the learner model (the Rasch model with an Elo update) and the trap catalog, and the child's profile is kept as a file in the family's Google Drive.
- **MathTrail Canvas** (`canvas-api`) — a tutor where the child solves by hand on a sheet. AI reads the answer, a program compares it with the key, and the tutor circles the place of the mistake and asks a leading question.

**What MathTrail gave:**
- **the mechanism** "AI reads, a program decides, the tutor asks", conceived as independent of the subject (R37 canvas-api). The main hypothesis — that AI understands the learner's free solution and reads the answer correctly — MathTrail did not manage to test (R60 canvas-api). NovaTrail's first slice will test it (R08);
- **the learner model and the rule for choosing a task**, which work without AI and are tested on the learner simulator (standalone);
- **a closed catalog of typical mistakes**, which turns an incorrect answer into a diagnosis (SPEC 1.3 standalone).

**Why a platform now.** MathTrail was tailored to olympiad maths for grades 1–6 and closed off everything else. NovaTrail is the same project, but the subject, the age and the canvas are moved out into modules (R01).

**What we take:**
- the principles of checking and of hints;
- the learner model and the simulator;
- the catalogs of topics, traps and techniques;
- 753 reference tasks with traps and 39 templates with solvers — standalone at commit 42b4408, and the first batch at 89986bc (R05 modules with the 2026-11-08 amendment);
- the framework of the services, the development environment and the delivery.

What is carried over from where is repositories 7.

**What we do not take as it is:**
- the canvas-api monolith — NovaTrail is cut into repositories from the first day (R10);
- "children only";
- "English only";
- a single AI provider.

MathTrail is frozen (R01).

## 3. For whom and why

| Who | What they get |
|---|---|
| A child (6–12) | solves the way they are used to: by hand, with a drawing, in words; gets a question instead of the "red pen"; learns to find the mistake themselves |
| A teenager | the same for school subjects and beyond them; more independence. Whether they have an account of their own, П-13 will decide |
| An adult learner | a language, physics, drawing — at their own pace, with a tutor that looks at the course of solution; with their own AI key — free (R07, О-4) |
| An adult beside a child: a parent, a guardian, a private tutor | sees the progress and the repeating mistakes; sets up the tutor; can run a session together with the child. Only the account owner — a parent or a guardian — manages the data (R06) |
| A module author: a methodologist, a teacher, an enthusiast, an organization | a ready lesson environment, tutor, learner model and engine — writes only the content; gets tools for checking and publishing |
| Teachers and schools — later | groups and a summary of frequent mistakes |
| An operator, self-hosting | open code: one can deploy one's own copy of the platform oneself (R12) |

## 4. How learning goes

```mermaid
flowchart TD
    E["The engine chooses a lesson or a task"] --> W["The learner works on the canvas"]
    W --> C{"Submission for checking"}
    C --> R["AI reads the work"]
    R --> P{"A program compares with the key"}
    P -->|"correct"| OK["“Correct” and what was read"]
    P -->|"not yet"| NY["What was read, the place of the mistake and the tutor's question"]
    P -->|"unreadable"| RW["A request to rewrite or to circle"]
    P -->|"no key"| FB["Feedback by the author's criteria"]
    NY --> W
    RW --> W
    OK --> M["The learner model is updated"]
    NY --> M
    FB -.-> M
    M --> E
```

A typed answer or a choice is not read by AI: a program checks it at once.

- **Three entries** — from the prototype:
  - **«Мои предметы»** ("My subjects") — the engine leads through the connected modules;
  - **«Карта навыков»** ("Skill map") — the learner chooses a skill on the map and sees what is mastered, what opens up and what it rests on;
  - **«Задача с моей бумаги»** ("A task from my paper") — the learner photographs a homework sheet and marks the tasks needed on the photo, and only their crops go to AI (О-11).
- **Two solving modes — "by steps" and "self".**
  - Step by step — the app leads through the module's solving steps, and the tutor speaks at each: in olympiad maths these are Pólya's steps.
  - On my own — the learner solves alone, and the tutor answers only when called.

  The default solving mode is chosen by an adult, for a new profile it is "by steps", and the learner switches it on a task (concepts 10).
- **The screens** are described in the prototype's README ([draft/README.md](../draft/README.md)): subjects and modules, the friend persona, canvases with tools, the steps panel, hints, the check, progress, the section for adults.

## 5. Modules and authors

A module is a package of one author (concepts 3). A module's path from the author to the learner:

```mermaid
flowchart LR
    A["The author writes a module: by hand or with the pipeline"] --> V["Check: schema, a graph without cycles, references, keys, eval"]
    V --> P["Publishing a version in the registry"]
    P --> U["The learner connects the module"]
    U --> K["The module's skills enter the learner model"]
```

- The **pipeline** helps the author: it marks up skills and traps and proposes variants of tasks. The author checks everything AI did before publishing. A published module is already unchanging data (R03).
- **Official modules** are written and maintained by the project; **third-party** ones by any author. Who publishes and how is О-9.
- **An update of a module does not break progress:** skill IDs are stable, and incompatible changes carry a table that maps the old IDs to the new ones (concepts 3).
- **A module is checked for reading quality.** Before publishing, the platform makes sure that AI reliably reads the work in this module's canvas kinds and answer kinds. The check runs on samples from the module's eval set: synthetic ones or ones made for eval by adult volunteers and authors, but not on learners' work (R02, concepts 3).

## 6. AI on the platform

**What AI does:**
- reads the learner's work — handwriting, speech, a photo, a drawing — and turns it into an observation (concepts 9);
- chooses the words — a hint, an explanation, praise — by rules and with checks (concepts 10);
- helps the author prepare a module — before publishing, under the author's check.

**What AI never does:** it does not decide whether an answer is correct, and it does not choose the next task (R03). The platform does not pass it a name, identifiers or an adult's data (privacy 5).

**Two AI routes** (R07):
- **platform AI** — by subscription, through the platform's agreements with providers;
- **own key** — an account owner who learns themselves connects their own key of OpenAI, Anthropic or another provider to their own profile of the category `adult` and uses the platform for free (R84; the 2026-11-02 amendment to R07).

**Models are admitted by eval.** Each AI capability has its own list of exact IDs of the models that passed that capability's eval. An own key does not open a model that did not pass eval (concepts 14).

**Age.** Providers have their own rules on minors, and the platform follows them (privacy 5.3). The check of 2026-10-18:
- The Gemini API may not be used in a service that people under 18 are likely to use. Since the platform is open to children, this route is closed for all its learners, adults too, — both through platform AI and with an own key. The check of 2026-10-22 found the same ban for Google Cloud's generative AI, Vertex AI too: Google's models are closed on the whole platform, for all learners, and whether they may be used in a separate deployment for adults only is a question for a lawyer (R47; П-3).
- OpenAI requires zero data retention for the personal data of children under 13 or under the age of digital consent of their country. OpenAI turns this mode on only by prior approval, and a family's ordinary key does not have it.
- Anthropic puts the safeguards on the organization that serves minors. What this means for a family's key the author decides by an analysis (R112; П-4).

Hence the recommendation: an own key is for adults, children learn through platform AI (О-4, О-5).

## 7. Principles

1. **A module is data.** The core knows no subject; a module gives a model no instructions (R02).
2. **A program gives the verdict.** AI reads the work and chooses the words; correctness is decided by a key or a predicate (R03).
3. **A false alarm is worse than no check.** Doubt is a request to rewrite, a failure is a neutral phrase, but never a "mistake" (R04).
4. **No deterministic check — no verdict.** An assessment by a rubric is feedback. A task from paper without a checked key gets no verdict and does not move the rating (R04, concepts 9.4).
5. **The tutor does not name the answer itself.** It asks one short question and points to the place in the learner's work (R05).
6. **The key does not go to the learner's device** until the task is solved (R05).
7. **The learner's work is untouchable.** The tutor writes only on its own layer (R05).
8. **We show what we read.** "Read: 6" — and the learner sees at once if AI read the wrong thing (R05).
9. **Without the "red pen" and pressure.** "Not yet" instead of "incorrect"; for children — without timers and competitions; without advertising and dark patterns.
10. **Progress survives a module update** (concepts 3).
11. **Any AI model — only after eval** (R07).
12. **Data — a minimum, and it is with the learner or the family.** Export and delete — in one step (R09).
13. **Openness.** The code, the documents and the content of the official modules are under Apache-2.0 (R12, R20), and the module format is an open standard.

## 8. Age and data

- The platform is for any age (R06). A child learns under an adult's account, an adult under their own.
- The learner's age and country are given by the account owner. The platform keeps the age category, not the date of birth (concepts 13).
- A minimum is kept about a child: the pseudonym, the avatar, the age category, the country, the interface language and the presentation style, and interests — once the format gives tasks a dressing for them (privacy 4).
- Strokes stay on the device. AI gets a picture of the work without a name or identifiers (privacy 1).

In detail — in [privacy.md](privacy.md).

## 9. Distribution and money

- **Open code** (Apache-2.0): anyone can deploy their own copy with their own keys.
- **Platform AI — by subscription.**
  - In the prototype this is a free daily quota of the tutor's help and the tariff Plus for $10 a month with a quota five times larger.
  - Prices and quotas are О-14. We first estimate the unit economics and then refine them with measurements, as in MathTrail Canvas (product 9 canvas-api).
- **An own key — free**, but not for everyone (О-4).
- **The mode without AI.** A typed answer or a choice, a check by a program, the author's hints — without calls to AI and at almost no cost. It is the free path, open to children too (О-5).
- **Grants** for open and free education. Open code, an own key and the mode without AI meet the requirement "open and free". MathTrail's package for grants — a logic model and a data register — is a sample for later.

## 10. The first slice

**The goal** is to prove universality: three modules of two unlike subjects — maths and writing — go through one platform, and the core holds no code of any subject (R08, R41).

**Module 1 — olympiad maths 1–6** from MathTrail:
- the learner is a child, the work is handwriting on a sheet. The manifest names adults too in the audience, `adult`: an adult tests the first app (R76);
- the answer is a number by hand; a choice of an option is for tasks whose answer is not a number or whose question points to options (R05 modules);
- Pólya's steps, techniques and traps;
- the explanations are in English, as the standalone tasks and the format examples are; the same module in Russian is another module, with its own name (R07 modules);
- 753 reference tasks of standalone: the first batch at commit 89986bc, the other 726 at 42b4408 (R05 modules with the 2026-11-08 amendment).

**Module 2 — school maths of grade 3** (R41):
- the learner is a child, the canvas is a workbook: the task's items stand on the template's unerasable layer;
- a task is a page of many items of one type (concepts 6);
- the answer is a number or a fraction by hand in an answer slot beside the item, and the verdict is for each item.

**Module 3 — short essays in English** (R41):
- the learner is of any age, a child or an adult, and the presentation style is by age; the canvas is a handwriting sheet;
- an essay by hand in a free form gets feedback by a rubric — an assessment by the author's criteria, not a verdict (R04). Assignments with a key — for example, choose the best first sentence — get a verdict;
- this is writing, not a language module: the explanations are in English, and there is no target language.

**In** (preliminarily):
- module format v0 and the three modules;
- a signed module index and the author's CLI, which checks modules (`module-kit`, R17);
- the learner model, the engine and the learner simulator;
- a measurement of AI reading — on samples that adult volunteers make for eval, among them imitating children's handwriting. Child samples — only with a separate consent (П-10) and before the beta: a goal for children's handwriting has to be checked on that handwriting itself. First comes the review board of `tutor`: the author solves tasks themselves and marks whether the model is right (R43). After it came a measurement of the course of writing on Claude models — on the author's sheet and 39 sheets that code drew: it was done on 2026-10-26 (R52), and the other measurements of reading are epic E4 of `tutor` (the 2026-10-26 amendment to R43);
- two canvas kinds — the handwriting sheet and the workbook;
- a check with a verdict and a tutor with a question; feedback by a rubric (R04);
- voicing of the tutor's words and of the module's open texts by the device's speech synthesis — only with voices by the rule of Т-13, without a server and without new data other than a setting in the presentation style (О-23). Its code — after the first app and before the first child (R76; В19 `app`; R07 app);
- a skill map for the three modules;
- an adult learner's account and the account of an adult with a child — this may be one account (R26);
- verifiable parental consent and agreements with AI providers — before the first child (П-1, П-3);
- platform AI — without payment, within a quota, for the participants of the closed slice (О-14); an own key — for adults (О-4);
- a web app for a tablet and a computer.

**Out:**
- third-party authors and widgets;
- the text canvas and language modules (R41);
- the registry service and the pipeline;
- tasks from paper;
- voice input;
- the learner's own text to the tutor: the conversation line of the first slice is buttons of requests, a hint and "explain differently" (R82; architecture 3.1). Own text — later, as an AI capability of its own of `tutor`, with its eval, a leak check in the reply and a row in privacy 4;
- a paid subscription;
- schools and teachers;
- the MCP channel;
- an offline mode and native apps.

**Success criteria:**
- the second and third modules needed no subject code in the core — only shared canvas kinds and checks;
- AI reads the work in all three modules with the target quality: the answer on a sheet, the answer slots in a workbook and the essay. This is a measurement on samples before the beta, like E2 in MathTrail Canvas; the main metric where there is a verdict is false alarms, and in canvas-api its goal is no more than 1 % (product 12 canvas-api). The mirror figure is "unreadable", and the learner rewrites it, while a false alarm on it does count toward this goal. The workbook's eval set measures such figures as a separate row: on the synthetic data of `tutor` the false alarms on them are 31–41 %, and on crossed-out ones about 16 % (the 2026-10-29 amendment to R56);
- the assessment by a rubric passes the eval of its AI capability by the measure of R71: the main one is false alarms on met criteria, and the goal is set by the measurement of `tutor` on adult volunteers' essays (П-16);
- on the learner simulator the engine behaves sensibly on all three graphs: it holds the success corridor where there is a verdict, goes in the author's order where there is none (concepts 4), does not loop and does not declare "mastered" too early;
- a child and an adult go through the lessons of their modules from beginning to end.

Module format v1 is fixed only after this (R08).

## 12. Risks and hypotheses

| Risk or hypothesis | Why it matters | What we do |
|---|---|---|
| AI reads the work badly in some subject | false alarms, the learner stops trusting the tutor | a measurement before the beta for each canvas kind and answer kind; in doubt — a request to rewrite (R04) |
| Universality turns out to be an illusion | the module format bends to maths | modules of two subjects in the first slice, and essays have no key; format v1 — after all three modules (R08, R41). The first slice does not test the text canvas and a language module (R41) |
| Others' widget code in an app where children learn | access to the page, the tokens and the network | the first slice has no others' widgets; later — an iframe sandbox (R16) |
| Own key | a weak model breaks the check; the key leaks; the provider's terms are broken | only models after eval; the key is not kept on the server, and on the device only by the key owner's choice (R84); own key — by age category (О-4) |
| Providers' terms on minors | children are left without AI, or the platform breaks the terms | a check of the terms with a date; platform AI under agreements that admit children; the mode without AI (privacy 5) |
| Voice | a child's voice is personal data, a voiceprint is biometrics (COPPA) | voicing — for everyone; children's voice input — after the author's decision by an analysis (R112; П-5) |
| The price of platform AI | the subscription does not pay for a subscriber's worst month | quotas; unit economics — an estimate, then measurements (О-14) |
| The quality of third-party modules | errors in keys; content that is not fit for children | a check at publishing; at first only official modules (О-9) |
| More than ten repositories for a small team | overhead on CI, versions and releases | the repositories are set up at once (R18), and code, CI and releases appear in the order of repositories 6; one repository template |
| The learner model does not carry over between subjects | the engine chooses tasks off the mark in a language and in drawing | a level per module, forgetting; a simulator with a criterion written down before the first run (concepts 11) |
