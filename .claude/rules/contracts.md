# The API contracts: `contracts/`

The API contracts are protobuf files by buf's rules, and the code buf generates from them. They are normative and in English (R42); their rules are R83. Their text is [contracts/README.md](../../contracts/README.md).

`just contracts-check` checks the API contracts in `contracts/` (R83): `buf.yaml` and `buf.gen.yaml` as R83 has them, before buf runs; the layout of `contracts/`; the rules of `contracts/README.md` that buf lets pass — proto3, no `json_name`, no unsigned type, the prefix `novatrail.` — by the image buf builds; `buf format` and `buf lint`; the test vectors of the observation, `contracts/vectors/observation/v1/`, which it reads by the same image and computes, as section 10 of `contracts/README.md` joins two observations and gives the verdict — but for what Starlark gives a predicate — and which the module of the contracts embeds as `contracts.Vectors` (R86); the test vectors of the rules the device and the runner share, `contracts/vectors/eval/v1/`, which it reads by the same image and computes by its own implementation of section 12 of `contracts/README.md` — how a history of writing folds, the groups of strokes, the crop, snapping and the boxes of a workbook (`tools/contracts/strokes.mjs`) —, and which the module embeds in `contracts.Vectors` too and the npm package carries (R94); the examples of the sample file of the eval protocol, `contracts/examples/eval/v1/`, which it reads by the same image, strictly, and holds to the rules of section 11 of `contracts/README.md` — the fields a sample's purpose and writer give it, its history or final geometry, its groups, boxes and crops, the chunks of their PNG (R93), and its markup, as far as the file alone holds it (R95) — and to those of section 12 of `contracts/README.md`: the numbers of every crop by the strokes the file holds, and the groups and boxes of a history (R94); the examples of the runner's report among them, `report-<case>.json`, which it reads the same way and holds to the form of section 14 of `contracts/README.md` and to the samples beside them (R95); `buf breaking` against the previous release, by its tag in spec's own history; and the code buf generates, which `just contracts` writes beside the `.proto` files and `contracts/` must hold file for file; and, with that code, its npm package `@altnovatrail/contracts`, built of the working tree, which `tsc` of `tools/` takes under `nodenext` and `bundler` and Node runs, reading each vector the package carries by its code (`tools/contracts/typescript.mjs`). buf is the `toolchain` stage's, the Go generators are tools of `contracts/go.mod`, and `protoc-gen-es` a package of `tools/`; a task that touches `contracts/` ends with it green, and a change to a `.proto` file runs `just contracts` first.

Another NovaTrail repository checks its sample files by the code that holds those examples, `just -f spec/justfile sample-check <file>…` from its root — and the files of a module's eval set together, with `--eval-set <module>` before them, by the rules of section 13 of `contracts/README.md` that need neither its package nor a key (the amendment of 2026-11-06 to R93) —, against the image buf builds of the `contracts/` of its spec/ submodule, in its `toolchain` stage and with no key (R93), and its files of the runner's report the same way, by the code that holds the examples `report-<case>.json`: `just -f spec/justfile report-check <file>… [--samples <file>…]`, with their samples after `--samples` when the reports are to be held to them too (R95).

The module of the contracts is checked by `just go-check` and the Go recipes too (`.claude/rules/go.md`), and the types of `<novatrail-canvas>` hold their marks to its message `Mark` (`.claude/rules/types.md`).
