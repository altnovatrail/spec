# The code of `tools/`

The checks of spec are code in `tools/`, on Node.js, with one `tools/package.json` and its lock file, `tools/package-lock.json`, from which the recipes install the packages (`_tools` in the justfile). Code of `tools/` comes with its tests: all of them at once and with their coverage are `just coverage`, which CI runs in three parts (`.claude/rules/ci.md`), and one tool's are `just <tool>-test` (`just --list`). Each part's own check and its tool are in the rule of that part, `.claude/rules/<part>.md`. A check that reads the documents takes a parsed document from the cache of the process, by the sha256 of its text — `parseMarkdown` and `markdownTree` of `tools/docs-check/markdown.mjs`, `readModuleFile` of `tools/format-check/yaml.mjs` —, frozen, so that a caller that changed it fails: the tests run a check on one trial copy after another and parse spec's documents once (RUN.md, T166).

`just licenses-check` checks the licenses of that lock file against the list in `tools/licenses/config.mjs` — the ASF's Category A, as R12 says — and its named exceptions; a task that changes `tools/package.json` or the lock file ends with it green.

`just tokens-report` prints where the tokens of this repository's Claude Code sessions on this machine went, from their transcripts: the calls of the model and the cache, what entered the context between calls — by tool, by file and by program — and what each carried, and what a session starts with; it prints numbers, paths and names alone, never what a transcript says (measurements 1). `--row` prints one row of the table of measurements 1.9, which the archive of an epic and the monthly measurement add (R145). Another repository runs it as `just -f spec/justfile tokens-report`; its tests are `just tokens-test`. The budgets of size that `docs-check` holds the documents to are `tools/docs-check/budgets.json`, and its tests are `just docs-check-test`.

`just translation-check <ref> <file>…` compares a document translated into English with its original at `<ref>`, unit by unit, and `just translation-anchors <ref> <file>…` rewrites the links to the headings a translation renamed, in every Markdown file of the repository; `tools/translation/README.md` is how a translation runs, and its tests are `just translation-test` (R143, the 2026-11-12 amendment). Another repository runs them as `just -f spec/justfile translation-check` and `translation-anchors`.

`.claude/settings.json` runs the hook `UserPromptSubmit` of `tools/session/`, which stops a prompt that starts another task than the one the session has led and names `/clear`: one task is one session (R143; measurements 1.7). «Сделай эпик E…» starts a task of its own, the orchestrator's epic (R156). The template's settings run it from `spec/tools/session/`, and it takes no package of `node_modules`, which another repository's `spec/` does not have; its tests are `just session-test`.

`tools/mockup/` is the runtime of NovaTrail's own that opens the interface mockup of `draft/mockup/` — the page, its states and its server (R148; RUN.md, T156). `just mockup` serves it, and another repository runs `just -f spec/justfile mockup`; the runtime and the server take no package of `node_modules`. `states.mjs` and the table "Screens and states" of `draft/mockup/README.md` name the same states, and a change of the sources changes both. Its tests are `just mockup-test`: every state on both devices under jsdom.

`tools/orchestrator/` holds the orchestrator's commands — `start`, `resume`, `status`, `wait` and `sync` —, which run a task of a repository as `claude -p` in that repository's container by `docker exec`, by the contract `executor.md` and the schema `status.schema.json`, and continue its session (R156). They run in spec's orchestrator container, from the orchestrator's own clone of spec, and take no package of `node_modules`. `just orchestrator` runs them from the working tree. Its tests are `just orchestrator-test`, with stand-ins for `docker` and `claude`: they hold the hand-written check of a status and the schema to the same values. `tools/orchestrator/README.md` says what a run's files hold, and its section «Сделай эпик E…» is the procedure the orchestrator's session follows; `tools/orchestrator/tasks/` holds the standard texts of the tasks it gives (RUN.md, T170).
