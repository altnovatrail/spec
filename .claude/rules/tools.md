# The code of `tools/`

The checks of spec are code in `tools/`, on Node.js, with one `tools/package.json` and its lock file, `tools/package-lock.json`, from which the recipes install the packages (`_tools` in the justfile). Code of `tools/` comes with its tests: all of them at once and with their coverage are `just coverage`, which CI runs in three parts (`.claude/rules/ci.md`), and one tool's are `just <tool>-test` (`just --list`). Each part's own check and its tool are in the rule of that part, `.claude/rules/<part>.md`. A check that reads the documents takes a parsed document from the cache of the process, by the sha256 of its text — `parseMarkdown` and `markdownTree` of `tools/docs-check/markdown.mjs`, `readModuleFile` of `tools/format-check/yaml.mjs` —, frozen, so that a caller that changed it fails: the tests run a check on one trial copy after another and parse spec's documents once.

`just licenses-check` checks the licenses of that lock file against the list in `tools/licenses/config.mjs` — the ASF's Category A — and its named exceptions; a task that changes `tools/package.json` or the lock file ends with it green.

`just tokens-report` prints where the tokens of this repository's Claude Code sessions on this machine went, from their transcripts: the calls of the model and the cache, what entered the context between calls — by tool, by file and by program — and what each carried, and what a session starts with; it prints numbers, paths and names alone, never what a transcript says (measurements 1). `--row` prints one row of the table of measurements 1.9, which the archive of an epic and the monthly measurement add, and `--classes` the table of measurements 1.14.2, the main calls of the orchestrator's executors by the class of the paths they named, over the folders that `--project`, given several times, names. Another repository runs it as `just -f spec/justfile tokens-report`; its tests are `just tokens-test`. The budgets of size that `docs-check` holds the documents to are `tools/docs-check/budgets.json`, and its switch `"comments": true`, there or in a repository's `docs-budgets.json`, turns on the check that each number of a decision in a comment of code names an entry of its log — `tools/docs-check/comments.mjs`, a scanner of comments that leaves strings and generated code out; `"citations": true`, the check of the rule of citations, `citation-rule.mjs`, under which no comment cites a decision and the first check does not run; its tests are `just docs-check-test`.

`just translation-check <ref> <file>…` compares a document translated into English with its original at `<ref>`, unit by unit, and `just translation-anchors <ref> <file>…` rewrites the links to the headings a translation renamed, in every Markdown file of the repository; `tools/translation/README.md` is how a translation runs, and its tests are `just translation-test`. Another repository runs them as `just -f spec/justfile translation-check` and `translation-anchors`.

`.claude/settings.json` runs the hook `UserPromptSubmit` of `tools/session/`, which stops a prompt that starts another task than the one the session has led and names `/clear`: one task is one session (measurements 1.7). «Сделай эпик E…» starts a task of its own, the orchestrator's epic. The template's settings run it from `spec/tools/session/`, and it takes no package of `node_modules`, which another repository's `spec/` does not have; its tests are `just session-test`.

`tools/mockup/` is the runtime of NovaTrail's own that opens the interface mockup of `draft/mockup/` — the page, its states and its server. `just mockup` serves it, and another repository runs `just -f spec/justfile mockup`; the runtime and the server take no package of `node_modules`. `states.mjs` and the table "Screens and states" of `draft/mockup/README.md` name the same states, and a change of the sources changes both. Its tests are `just mockup-test`: every state on both devices under jsdom.

`tools/orchestrator/` holds the orchestrator's commands — `start`, `resume`, `stop`, `status`, `wait`, `next`, `rebuild`, `create` and `sync` —, which run a task of a repository as `claude -p` in that repository's container by `docker exec`, by the contract `executor.md` and the schema `status.schema.json`, and continue its session; `rebuild` and `create` build a repository's container by the Dev Containers CLI in a helper container; `xrepo` — `up`, `status`, `test`, `serve`, `stop`, `sync`, `push`, `gate`, `pin`, `wait-release`, `ship` and `down`, `just xrepo` — runs a task across repositories in the clones of `.epics`, wired to one spec, its stand of api, app and canvas, `stand.mjs`, its gate, `gate.mjs`, and its ship, `ship.mjs`. They run in spec's orchestrator container, from the orchestrator's own clone of spec, and take no package of `node_modules`. `just orchestrator` runs them from the working tree. Its tests are `just orchestrator-test`, with stand-ins for `docker`, `claude` and `devcontainer`, and for `just`, `go`, `npm` and GitHub in xrepo's made-up world, `test/world.mjs` and `test/github.mjs`: they hold the hand-written check of a status and the schema to the same values. `tools/orchestrator/README.md` says what a run's files hold, and its section «Сделай эпик E…» is the procedure the orchestrator's session follows, and its section on `xrepo` what each command does and what the stand's files hold; `tools/orchestrator/tasks/` holds the standard texts of the tasks it gives.

`tools/patchcov/` counts the coverage of the lines a branch changed from its merge-base, by `coverage/go.out` and `coverage/lcov.info`, as Codecov counts `codecov/patch` — a partial line a miss, cut down to two decimals (sources 11.5) —, against the target of `.github/codecov.yml`; `just patchcov`, in another repository `just -f spec/justfile patchcov`, and xrepo's gate run it, with no package of `node_modules`. A change of Codecov's rule changes it and its record. Its tests are `just patchcov-test`.
